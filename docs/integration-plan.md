# 移動式自然セラピーインフラの実装計画（舞台 × 役者の連携）

研究計画「高密度都市における移動式自然セラピーインフラの構築」（自律神経の過渡応答の解明と、JITAI・都市シミュレータによる最適配車）を、2 つのリポジトリの連携で実現する計画です。

## 役割
| リポジトリ | 役割 | 技術 |
| --- | --- | --- |
| [tokyo-green-simulator](https://github.com/stzn/tokyo-green-simulator) | 舞台: 都市緑化デジタルツイン。PLATEAU の建物、街路樹、公園、地形から、地点ごとの日射遮蔽と緑の文脈を計算する。配車結果を地図に表示する | TypeScript、React、deck.gl、静的配信 |
| 本リポジトリ | 役者: 仮想移動緑化シミュレータ。舞台の地点で、PET の計算、ポッドの配車・散水、JITAI の模擬を行う。過渡応答 R(t) と階層モデルの解析基盤も持つ | Python、Pydantic、LangGraph |

受け渡しは JSON のファイル（[contracts/](../contracts/README.md)）で行い、舞台は静的配信のまま、サーバーなしで連携する。

## 設計の方針
- **判断は計算で行い、LLM は説明に使う。** チェックリスト読解の研究（[まとめ](checklist-reading-summary.md)）で、小さい LLM は AND 条件の表を読めず、世界側が計算した答えを渡すと安定した。配車・介入の判断は規則・最適化で計算し、LLM は通知文などに限る。
- **研究の数値は画面の状態で変えない。** 舞台の既存方針（絞り込みに関係なく全件で数える）に合わせる。
- **個人の計測値は外に出さない。** 舞台の既存方針（HRV はメモリにだけ置く）に合わせ、`stage.json` の需要には集計値だけを入れる。

## フェーズ
| # | 内容 | リポジトリ | 依存 |
| --- | --- | --- | --- |
| 0 | データ契約 v1（`stage.json`・`dispatch.json`）。スキーマとサンプルを両リポジトリのテストで検証する | 両方 | なし |
| 1 | 舞台: パイロット区域（大手町・丸の内）の候補地点を抽出し、PLATEAU の建物の高さと太陽位置から、時間別の日射遮蔽率と天空率を計算して `stage.json` を書き出す | 舞台 | 0 |
| 2 | 役者: A/B/C の固定をやめ、`stage.json` から N 地点の世界を作る。PET を計算し、複数ポッドの配車（貪欲法から始める）と散水を行い、`dispatch.json` を書き出す。baseline と比較する | 役者 | 0 |
| 3 | 舞台: `dispatch.json` を読み込み、時刻スライダーでポッドの位置と快適度を地図に重ねる | 舞台 | 0（2 の出力で確認） |
| 4 | 役者: JITAI の模擬。4 段階（日内変動を補正した過緊張の検知 → 予定の空き枠 → 徒歩圏のポッドの空き → 二段階の PET 安全判定）を規則で実装し、合成のワーカーで回す | 役者 | 2 |
| 5 | 役者: 解析基盤。RR 間隔から ln(HF) の時系列を作り R(t) を当てはめる（問い①）。PET・騒音を共変量にした階層モデル（問い②）。合成データで先に完成させる | 役者 | 0（PET は 2 と共有） |

0 の後、1・2・5 は並行して進められる。3 は 2 の出力が出てから、4 は 2 の後。

## 前提と未決事項
- パイロット区域: 大手町・丸の内（役者の気象データと同じ地点）。
- HRV の機器は未定。ln(HF) と R(t) には RR 間隔が要る（Apple Watch の書き出しは SDNN が中心）。解析基盤は合成の RR データで先に作り、機器が決まったら読み込み部分を足す。
- 問い①②の実測（2×2 の実験）には倫理審査が要る。ソフトウェアの計画の外にある。
- 日影の計算は、PLATEAU の建物の高さによる遮蔽だけを扱う（街路樹の樹冠による遮蔽は、樹高・樹冠幅のデータがそろわないため v1 では含めない）。
