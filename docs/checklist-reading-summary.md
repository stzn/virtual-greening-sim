# 研究のまとめ: LLM はチェックリストをどこまで正しく読めるか（v1〜v26）

## 問い
チェックリスト形式のプロンプト（「かつ」「未満」を含む条件の表）を、LLM はどこまで正しく読めるか。読めない場合、プロンプトの書き方で改善できるか。

## 方法
- 評価（`evals/features/`）は 59 シナリオ。各シナリオを 5 回試行（初期条件を決定的に揺らす）し、4 回以上が期待どおりなら通過とする。
- モデルはローカルの Ollama（qwen3:8b / 14b、llama3.1:8b、qwen2.5:7b）と Claude Haiku 5.5・Sonnet 5.5。ローカルは API 費用なし。
- 各結果は 1 回の評価で、確率の差としては粗い（再現確認をしたのは v24 の qwen3 8b・14b だけで、同じ結果だった）。

## 結論（先に）
1. **読み取りの弱さは、複数条件の AND を保持して評価する力にある。** 小さいモデル（8b 前後）は、行 #1 を既定として扱い、「5 つのうち 1 つが × なら非該当」という評価を落とす。誤りの多くは「該当」と書きながら事実と食い違う。
2. **プロンプトの書き方（文章・説明・書式）では、この力は大きく伸びない。** 文章を長く強くする、否定を含む複合条件を足す、表を質問の流れに書き換える（v26）は、いずれも効かないか誤差の範囲だった。
3. **効いたのは、世界が条件の真偽を計算して渡すこと。** 条件ごとの真偽（観測キー）で改善し、世界が「最初に当てはまる行の番号」まで渡す方式（v23/v24）で大きく伸びた。
4. **ただし v23/v24 は、表を読む力の測定ではなくなる。** モデルは、世界が出した答えの番号に従っている。効果は「世界の計算結果に従う力」の改善であり、読解力の改善と区別して扱う。
5. **失敗の型はモデルごとに違う。** 評価の通過数だけでは原因が分からない（下表）。

## 結果（通過数 / 59）
| モデル | v21（既定） | v24（世界が行番号を渡す） | 主な失敗の型 |
| --- | --- | --- | --- |
| qwen3:8b | 35 | 55 | 行 0（どの行にも当てはまらない）の雨が近い状況で、行 #1 へ引き戻されて B へ移動 |
| qwen3:14b | 58 | 59 | ほぼなし（v24 は 2 回とも 59） |
| llama3.1:8b | 17 | 35 | 最終回答で行動を宣言しながらツールを呼ばない（宣言 91 試行のうち 36）、行番号に従わない |
| qwen2.5:7b | 23 | 47 | 「何もしない」への偏り（宣言と実行は一致） |
| Claude Haiku 5.5 | 51 件通過（全 59 は未評価） | 59 | なし |
| Claude Sonnet 5.5 | 51 件通過 | 未評価（API 費用） | — |
| mistral 7B / granite3.3:8b | — | — | ツールを 1 回も呼べず、比較の対象外（mistral の 28 は「何もしない」が期待の件のみ） |

Haiku と Sonnet の v21 は、全 59 件になる前の 51 件で評価した。

## 版の経緯（要点）
- v1〜v21: 観測キー（`heat_trigger`・`moisture_below_30` など）を世界が計算して渡し、誤読する 1 点だけに短い説明を添えた。境界値（ちょうど 30、15、33 など）を含め、qwen3:14b・Haiku・Sonnet が通過する形に収束した。
- v22（往復を観測キーで渡す）: 狙った件は直ったが別の 2 件が退行し、不採用。
- v23・v24: 世界が `checklist_row` を渡す。8b は 35 → 52 → 55、14b は 58 → 59。v24 は「行 0 は何もしない」を明記。
- v25: v24 に「表を自分で当てはめ直さない」を追記。8b の行 0 は直らず不採用。
- v26: 表を 1 項目ずつ確認する質問の流れに書き換え（世界の答えは渡さない）。8b は 35 → 38 で誤差の範囲、不採用。

詳細は [prompt-history.md](prompt-history.md)（版ごとの変更と到達点）と [eval-results.md](eval-results.md)（各評価の記録）にある。

## 限界
- 各結果は 1 回の評価。通過数の差が数件のときは、誤差の範囲かもしれない。
- シナリオは 59 件で、行 0（どの行にも当てはまらない）の型は少ない。8b の弱点の一つがここにあるため、件数を増やす余地がある。
- ローカルモデルは 7〜14B。大きいモデル（Sonnet の全 59 件、v24）は未評価。
- 条件の真偽を世界が計算する方式は、実運用で世界側にその計算を持たせられる場合に限り使える。

## 今後の候補
- 行 0 や雨が近い状況のシナリオを増やし、n=5 の粗さを減らす。
- Sonnet 5.5 での v24 評価（概算で約 $10。Haiku で退行がなかったため必要性は低い）。
- 既定を v24 に切り替えるかは、「表を読む力」を測る目的と両立しないため、現時点では v21 のままにする。
