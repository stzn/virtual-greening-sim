# 研究のまとめ: 資源配分のボトルネックは「計画能力」か（scarce_water）

数値と全文の根拠は [eval-results.md](eval-results.md)（2026-10-27〜11-02 の各節）。ここでは結論・根拠・限界だけを整理する。

## 問い
猛暑で水が少ない一日（scarce_water、24時間）で、LLM エージェントの成績が伸びない。
原因は、時間をまたいだ計画（いつ・どれだけ水を使うか、いつ退避するか）の能力か。

## 結論（先に）
1. **思考（拡張思考）は、qwen3:14b では効く。主な機構は「ピーク前の早めの退避」である。** 水の配分そのものの改善ではない。
2. **「思考が効く」の中身は、モデルで違う。**
   - qwen3:14b: 予報からピーク前の退避を組み立てること自体に思考が要る。指示の一文では代替できない。
   - Claude Haiku 5.5: 思考オフでは、移動を「温存する資源」として扱い、退避を先送りする癖があった。その癖を直す一文（移動は温存しない）で、思考オフでも思考ありと同等になった。
   - Claude Sonnet 5.5: 思考オフが作れない。思考ありでは、全構成が1ステップ目からピーク前の退避を計画し、plan_early 系（観測と指示）が hybrid の「移動コストを理由にした先送り」を直した（+4.7）。一文の追加の寄与は小さい（+1.3）。
3. **観測（計画観測）と指示の一文は、単独では効かない。** 組み合わせるモデル・思考の有無で結果が変わる。
4. **計画能力が唯一のボトルネックとは言えない。** モデルごとに、ボトルネックは「予報からの先読み」（qwen3）か「判断の癖」（Haiku）だった。

## 機構の根拠（判断理由の全文で確認）
- **qwen3 の思考あり**: 予報のピークから逆算して早めに退避する。思考オフは判断理由が短く、現在の値と短い見通しで判断し、退避が遅い。移動の温存には触れない。
- **Haiku の思考オフ（v3・v4）**: 07時の同じ判断点で、散水を先にし、「移動はバッテリーと移動予算を消費する」と先送りを繰り返した。v3 は水が尽きてから退避、v4 は退避せず散水が失敗した。思考ありは、予報から逆算して07時に退避した。
- **plan_early_move（Haiku）**: 08〜09時に、「ピーク前に動くのは移動のよい使い道」として退避した。移動の温存への言及は消えた。

## 安全性の確認
- 退避が要らない状況（wet_rain・dry_before_rain）で、plan_early_move も移動は全6実行で0回。不要な移動は誘発しなかった。
- dry_before_rain では plan_early_move が plan_early より平均 −4.2（SE 2.5、5件）。偶然の範囲と区別できず、一文のせいとも言えない（散水の開始時刻と量のばらつきが原因で、判断理由に一文への言及はない）。

## tradeoff 状況（10時間、開始時点でピークの最中）での確認
- plan_early_move は plan_early と同等以下（平均 −3.2、SE 2.0）。退避が22〜14時とばらつき、遅い傾向。baseline（14時に即退避）をどの LLM 構成も上回らなかった。
- 全文では、一文があっても「まず散水して、次のターンで再判断」と先送りしていた（v0 は水が尽きた22時に退避）。一文の効果は scarce_water のように、ピークまで時間がある状況に限られる可能性がある。
- 思考ありは tradeoff でも14〜15時に退避し、状況を問わず安定していた。

## Sonnet 5.5（思考あり）での確認（stress12、scarce_water、n=5）
Sonnet 5.5 は思考を無効にできない（API が拒否する）ため、全構成を思考ありで比べた。

| 構成 | 最終健康度 | baseline 比（対の差） | 退避の時刻 |
| --- | --- | --- | --- |
| baseline | 74.0 | - | 10〜12時 |
| hybrid+think | 78.8 | +4.8（SE 2.2）、4-0-1 | 3〜7時 |
| plan_early+think | 83.5 | +9.5（SE 2.0）、5-0-0 | 0〜2時 |
| plan_early_move+think | 84.8 | +10.8（SE 2.1）、5-0-0 | 0時（全5件） |

- 全構成が1ステップ目から「ピーク前に日影へ退避する」計画を立てた。hybrid は「移動はバッテリーを使う」「移動予算は2回」を理由に朝まで待つ傾向があり、plan_early 系は夜のうちに動いた。
- plan_early_move と plan_early の差（+1.3）のうち、退避の時刻が違うのは1件（02時と00時）だけ。他は散水のばらつきで、一文の寄与は小さく、偶然の範囲。
- 思考オフが作れないため、思考そのものの寄与、思考オフでの一文の効果は確かめられていない。

## 散水の失敗: エラーの message に次の一手を添える
- Haiku の散水の失敗は、すべて 50ml 未満の要求だった。50 を指定すれば残量まで散水できる（世界が切り詰める）のに、モデルは「散水できない」と誤解していた。
- 失敗は残し（再判断のきっかけを消さない）、エラーに「50を指定すると残量まで散水します」を添えた。
- 失敗の直後に 50 を指定して成功した割合: details に置くと 1/6、message の先頭に置くと 6/7。message に置いた段階では、失敗の件数（3〜4件）と最終健康度は変わらなかった。
- 同じ情報でも、読まれるかは置き場所で大きく変わる。
- 続いて irrigate の説明文にも「残量が50ml未満でも50を指定すれば残量まで散水」を追記した（stress10）。タンク残量が50ml未満のときの最小量未満の要求は 5件 → 0件で、残量の誤解による失敗は見られなくなった。
- 残った4件は、タンクに52〜105mlあるのに30〜40mlを要求した失敗。全文では、計画観測の「残り時間あたりの水」を見て、水を温存するために少量を選んでおり、最小量の制約は計画の段階で見落とされていた。4件とも直後に50mlで成功し、健康度への影響も見られないため、これ以上は対処しない。

## 限界
- 1つの世界（scarce_water）中心。n=5。モデルは3つ（qwen3:14b、Haiku 5.5、Sonnet 5.5）。
- Haiku は temperature を指定できず、再現性は qwen3 より低い可能性がある。
- 一文（MOVE_FIRST_HINT）は、Haiku の失敗の観察から作った。この状況に合わせた調整であり、他の状況・他のモデルでの一般化は未検証（qwen3 では効かなかった）。
- Sonnet 5.5 は思考オフが作れず、思考オフでの一文の効果は未検証。
- 思考の全文は、Haiku・Sonnet では要約（summarized）で、内部の全思考ではない。因果は、判断理由として引用できる範囲での観察。
- 散水の失敗は、説明文の追記で残量の誤解に由来するものは消えたが、最終健康度の改善は確認できていない（n=5、揺らぎの範囲）。説明文の追記は全実行のプロンプトを変えるため、旧実験との比較は参考。
